# 事克郎王国

一个以“事克郎王国”为世界观的游戏化任务管理网页原型。  

## 项目简介

`事克郎王国` 面向需要处理大任务、容易拖延、又希望界面更有陪伴感与反馈感的用户。  
它将任务拆解、待办管理、任务执行、卡牌收集与回顾系统结合在一起，让“做任务”变成一次在昆虫王国中滚动前进的旅程。

目前仓库中已经完成了：

- 基于设计导出图的前端页面复原
- 多页面单页应用式切换与基础动效
- 抽卡、任务执行、待办、卡牌库、个人中心等主要页面原型
- 本地 mock 数据与任务流转逻辑
- 适配桌面端展示的固定舞台缩放方案

## 项目特色

- **世界观驱动的任务体验**  
  用事克郎王国、角色陪伴、奖励卡牌和任务进度反馈替代传统待办工具的冰冷感。

- **高还原视觉原型**  
  当前页面主要围绕 `Page_View/` 中的设计导出图进行复原，尽量保持构图、素材、氛围和交互热点一致。

- **可继续扩展的前端骨架**  
  现阶段使用原生 HTML / CSS / JavaScript 与 mock 数据驱动，便于后续接入 AI 拆解、持久化存储、账号系统等能力。

## 核心功能闭环

当前原型已经具备一条可点击体验的核心路径：

1. 进入首页，选择功能入口
2. 在 `AI任务拆解` 中生成任务步骤
3. 将拆解结果加入任务池
4. 在 `待办管理` 或 `抽卡页` 中选择任务
5. 进入 `任务执行页` 开始 / 暂停 / 完成任务
6. 完成后获得奖励反馈，并流转到 `卡牌库` 或 `任务回顾`

这条流程当前以 mock 数据驱动，但页面关系、跳转语义和基础动效已经建立。

## 技术结构

当前项目保持轻量化原型结构：

- `index.html`  
  应用入口

- `src/app.js`  
  页面渲染、路由状态、页面切换、交互逻辑

- `src/styles.css`  
  全局样式、页面布局、舞台缩放、视觉还原

- `src/data.js`  
  页面展示所用静态数据、角色、任务、卡牌、成就等

- `src/mockServices.js`  
  mock 任务拆解、待办生成、任务映射与奖励逻辑

- `src/deepseekService.js`  
  前端 AI 拆解适配层，调用站内 `/api/decompose-task` 代理接口

- `netlify/functions/decompose-task.mjs`  
  Netlify Functions 后端代理，负责安全读取 DeepSeek API Key 并转发拆解请求

- `Assets/`  
  项目使用的美术素材资源

- `Page_View/`  
  设计导出图，用于页面复原参考

## DeepSeek AI 配置

项目已经接入 DeepSeek 任务拆解代理。API Key 不会出现在前端代码、浏览器 localStorage 或 GitHub 仓库中，正式部署时请在 Netlify 环境变量里配置：

- `DEEPSEEK_API_KEY`：必填，你的 DeepSeek API Key
- `DEEPSEEK_MODEL`：可选，默认 `deepseek-v4-pro`
- `DEEPSEEK_BASE_URL`：可选，默认 `https://api.deepseek.com`

本地如需完整测试 AI 接口，建议使用 Netlify CLI：

```bash
netlify env:set DEEPSEEK_API_KEY sk-your-deepseek-api-key
npm run dev:netlify
```

如果只运行 `npm run dev`，页面仍可预览，AI 请求会因为没有 Netlify Function 或没有环境变量而自动回退到本地 mock 拆解，便于继续调试视觉与交互。

## 用户注册与登录

项目已接入 Netlify Identity，支持邮箱注册、登录、邮箱确认回调和退出登录。前端不会保存用户密码，登录状态由 Netlify Identity 维护。

部署到 Netlify 后，请在站点后台启用：

1. 进入 `Project configuration > Identity`
2. 启用 Identity
3. 根据需要设置 `Registration` 为开放注册或邀请注册
4. 开发测试阶段可开启 `Autoconfirm`，正式环境建议保持邮箱确认

当前站点地址：

```text
https://done-beetle-kingdom.netlify.app
```

说明：Netlify Identity 需要在线部署环境才能完整测试，本地 `npm run dev` 主要用于页面样式和交互预览。

### 测试账号建议

前端代码不能替你在 Netlify 后台直接创建真实账号。建议在 Identity 启用后，用下面这组信息在网站注册测试：

```text
昵称：测试事克郎
邮箱：beetle.test.001@example.com
密码：BeetleKingdom2026!
```

如果后台未开启 `Autoconfirm`，注册后需要在 Netlify Identity 的 Users 列表里手动确认该用户，或通过真实邮箱接收确认邮件。`example.com` 邮箱只适合作为后台手动确认的演示账号；若要测试邮件链路，请换成你能接收邮件的邮箱。
